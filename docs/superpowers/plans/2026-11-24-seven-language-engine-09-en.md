# Seven-Language Engine — Plan 9: English (en) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** An English language pack on the staged core that conjugates every verb (real or invented) in 24 catalogue entries, explains each form step by step in English and Dutch with a citation per rule, and passes all 18,270 cells of the 145-file English oracle with 480 sourced corrections.

**Architecture:** A `StagedGrammar<EnglishLexeme>` in `src/languages/en/`, laid out like Plan 2's Dutch pack: classification (lexicon of ~180 irregular paradigms, closed-list prefix inheritance, stress decision) → stem (the plain form, or listed whole words) → ending (∅ / -s / -ed / -ing) → eleven spelling rules as `JunctureRule`s (region-forked for British/American final l) → 18 periphrases (have, be, will, would, let's, to) → a clause that only adds the subject pronoun. The oracle is parsed positionally and compared with a pack-local region check.

**Tech Stack:** TypeScript 7 strict, Node 26, Vitest 5, cheerio (dev, corpus scripts only), npm workspaces. No new dependencies.

**Spec:** `docs/superpowers/research/2026-11-24-en-grammar-design.md` (rule tables, lexicon, oracle analysis; cited below as "design §n"), within `docs/superpowers/specs/2026-11-24-seven-language-engine-design.md` § "English (en)". The design's "Deviations" table lists where it departs from the approved spec.

**Builds on:** Plan 2 (`docs/superpowers/plans/2026-11-24-seven-language-engine-02-core-completion-and-dutch.md`), all of Part A: `LanguagePack.subjects` / `subjectsFor` and `ClauseContext.subject` (on the branch as `6dcad74`), `classify` returning a `Fork`, `cellOf(target, lexeme)`, `Periphrasis.applies`, `ClauseContext.agreeing`, `PartFeatures.aspect`, the `./core` authoring surface, the typed option schema, and the corpus model with labelled queries, `remaps`, `unmodelled`, `corpusCell({ … })` and `infinitiveFromFileName`. Dutch (Part B) is the layout model. Read `src/core/staged.ts`, `clause.ts`, `periphrasis.ts`, `juncture.ts`, `fork.ts`, `tests/toy/pack.ts` and Plan 2's Dutch files before Task 1.

## Review Focus

1. **One verb, two accepted spellings.** `travel` past must return `travelled` (region GB) and `traveled` (US), GB preferred unless `region: 'US'`; a compound never mixes them (`I would have travelled` exists, `travelled` + a US word never does); `learn` returns learned + learnt (GB). → Task 3 and Task 4 tests.
2. **A verb with two paradigms.** `hang` returns hung (pattern `hung`) and hanged (pattern `hanged`) with their glosses; `classHint: 'regular'` keeps only hanged; `underlie` inherits only lay/lain; identical present forms appear once per paradigm. → Task 2 and Task 3 tests.
3. **An invented verb that looks prefixed or like an irregular.** `outswim` → outswam; `reblit` (not a known base) is regular with an assumed final stress → reblitted; `behave`, `relay` are never `behad`, `relaid`; `forecast` is listed, not inherited. → Task 2 tests.
4. **A polysyllable whose stress the spelling does not show.** `prefer` → preferred and `enter` → entered with no assumption (listed); `visit` → visited and `trimbit` → trimbited with `en.classify.assume-nonfinal-stress`; the `stress` hint overrides both ways. → Task 2 and Task 3 tests.
5. **Input a learner or the trainer may pass.** `To Walk` conjugates walk; `give up` and `must` are `INVALID_INFINITIVE`; `subject: '3sg.f'` gives `she walks`; a subject on the imperative that the imperative does not have (`3sg.m`) is `INVALID_TARGET`; every form of the test verbs explains in `en` and `nl`. → Task 2 and Task 4 tests.
